# 構成とプロトコル

TVのsitatvserviceへ自作libtsd.soを読み込み、常駐ネイティブコードで選局とTS読取りを行います。起動フックと補助ファイルはMagisk側・`/data` に置き、vendorパーティションを書き換えません。

| 接続 | 用途 |
| --- | --- |
| TCP 40556 | チューナー0のTS、1クライアント |
| TCP 40558 | チューナー1のTS、1クライアント |
| TCP 40557 | キー認証付き選局・状態取得 |
| 127.0.0.1:40555 | キー認証付き開発用コンソール |

選局APIは1行の `AUTH <64桁hexキー> TUNE <0または1> <ONID> <TSID> <SID>`、状態取得は `AUTH <キー> STATUS`、2系統目停止は `AUTH <キー> STOP 1`。数値は10進です。正常時は `OK`、異常時は `ERR` から始まる1行を返します。通常利用ではBonDriverが処理します。ローカルのroot診断には `tsctl --status` を使えます。

チューナー0は既存のTV/PVR経路、チューナー1は独立したFPIフロントエンド・TSIO・2MBのTSRリングを使います。TVのDBから周波数を取得し、CRC検証したPAT/PMTから選択サービスとECM PIDを発見します。B-CAS処理は既存ファームウェアのPVR経路へ委譲します。CWの値を読み出したりログへ出力したりしません。

ECMキューがデータへのポインターを保持するため、64個の固定バッファを使用します。既存の直列PVR処理の呼出し完了を値を読まずに計数し、後続処理へ進んだことを確認して再利用します。停滞時は未処理バッファを上書きせず、新規ECMを拒否してエラーを計数します。現在の実装が設定するPVRハンドルは主映像・主音声の2つです。

TSは受信クライアントがいない間も読み捨ててリングを排出します。遅いクライアントは切断し、BonDriverは再接続します。Windows側のキューは32MBに制限します。チューナーごとの排他制御により同じ番号の重複使用を防ぎます。

機器固有キー、実際の接続INI、署名秘密鍵、放送TS、ベンダーバイナリー・逆解析出力はソース配布対象外です。LAN内向けの構成で、インターネットへのポート公開は実装していません。
