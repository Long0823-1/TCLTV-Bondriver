# 構成とプロトコル

TVのsitatvserviceへ自作libtsd.soを読み込み、常駐ネイティブコードで選局とTS読取りを行います。起動フックと補助ファイルはMagisk側・`/data` に置き、vendorパーティションを書き換えません。

| 接続 | 用途 |
| --- | --- |
| TCP 40556 | チューナー0のTS、1クライアント |
| TCP 40558 | チューナー1のTS、1クライアント |
| TCP 40557 | キー認証付き選局・状態取得 |
| 127.0.0.1:40555 | キー認証付き開発用コンソール |

選局APIは1行の `AUTH <64桁hexキー> TUNE <0または1> <ONID> <TSID> <SID>`、状態取得は `AUTH <キー> STATUS`、2系統目停止は `AUTH <キー> STOP 1`。数値は10進です。正常時は `OK`、異常時は `ERR` から始まる1行を返します。通常利用ではBonDriverが処理します。ローカルのroot診断には `tsctl --status` を使えます。

両チューナーともFPIフロントエンドと独立した2MBのTSRリングを使い、TVのAVプレイヤーや映像デコーダーを起動しません。チューナー0は通常の復号バンクに対応するTSIO 0を使い、未作成なら専用入力を初期化します。チューナー1は別のTSIOとPVR復号バンクを使います。TVのDBから周波数を取得し、CRC検証したPAT/PMTから選択サービスとECM PIDを発見します。B-CAS処理は既存ファームウェアの通常・PVR経路へ委譲します。CWの値を読み出したりログへ出力したりしません。

ECMキューがデータへのポインターを保持するため、64個の固定バッファを使用します。既存の直列PVR処理の呼出し完了を値を読まずに計数し、後続処理へ進んだことを確認して再利用します。停滞時は未処理バッファを上書きせず、新規ECMを拒否してエラーを計数します。主映像・主音声に加え、同じECMを使う追加ESを最大12 PID登録します。完了判定は固定の2ハンドルではなく、実際の登録数を加算した累積呼出し数で行います。

TSは受信クライアントがいない間も読み捨ててリングを排出します。遅いクライアントは切断し、BonDriverは再接続します。Windows側のキューは32MBに制限します。チューナーごとの排他制御により同じ番号の重複使用を防ぎます。

機器固有キー、実際の接続INI、署名秘密鍵、放送TS、ベンダーバイナリー・逆解析出力はソース配布対象外です。LAN内向けの構成で、インターネットへのポート公開は実装していません。

## TVのチャンネルスキャン結果（v0.3.0）

Windowsツールは初回設定・局更新時にroot ADBでTV Providerのchannelテーブルを読み、TYPE_ISDB_Tかつ表示対象のAVサービスを抽出する。EN_TCL_DTVおよびSERVICE_TYPE_AUDIO_VIDEOを受け付け、衛星・データ専用・非表示を除外。地域IDや局名の固定表は使用しない。

2系統のINIをUTF-16 LE BOM付きで保存し、[Channels] Countと[Channel0]以降のName/DisplayNumber/ONID/TSID/ServiceIDを使用。上限512件。DLLインスタンス生成時に読み、名前のポインターとチャンネルインデックスはインスタンス存続中に変更しない。更新後は視聴ソフトを閉じてDLLを読み直す。ONIDとTSIDは独立してTUNEへ送る。局一覧のない旧INIには地域プリセットでフォールバックしない。

局一覧が変わった場合のみ、対象BonDriverの.ch2をバックアップ・退避し、TVTestでの再スキャンを促す。同じ局一覧の更新では.ch2を保持する。日常のBonDriver動作は保存済みINIを読むためADB不要。TVの起動時は有効な保存局を復元し、ない場合はTV Providerの地デジ登録から初期局を選ぶ。

## C/Nと多サービスの取得（v0.4.0）

認証付き SIGNAL 0 / SIGNAL 1 で、ロック・C/N（ミリdB）・強度（%）・品質（%）を返します。BonDriverは専用スレッドで約1秒ごとに取得し、GetSignalLevelはキャッシュからC/Nを返します。

PAT/PMTのCRCを検証し、PAT内の全サービスのPMT/PIDを収集します。発見時に全TSを取得し、その後はPIDフィルタの和集合へ切り替えてPVR復号経路を維持します。第1系統では映像・音声を含む対象ESすべてに通常のdemuxフィルタを作成し、選局前に所有フィルタを解放します。第2系統はPVR用の追加PID登録を使います。データ放送を捨てたり、未復号パケットの暗号化フラグだけを消したりしません。

起動時のtsctl --tuneは、保存局のPMT/PIDと追加復号フィルタを作り直します。PAT 1セクション、32サービス、PID合計63、第1系統は映像・音声2 PID＋追加復号ES 12、第2系統の追加復号PIDは12が上限です。別ECM群やPMT変更は自動追従を保証しません。

## 復号枠の割り当て（v0.4.1）

第1系統では、既存の映像・音声用の通常復号ハンドル2個も専用demuxフィルタへ接続します。追加枠12個だけへ全ESを登録していたv0.4.0と異なり、13 ESを持つ日テレ等も選局できます。鍵の値にはアクセスせず、既存ハンドルIDのみを取得し、対応ファームウェアのコード配置を再検査します。最大14 ESで、初期化はTVの映像プレイヤーを起動しません。

ES単位のCA記述子がnull ECM PID（0x1fff）を指定した場合は、プログラム単位のCA指定を上書きする非暗号化ESとして扱います。TSのPID和集合には保持し、復号器への登録からだけ除外します。TOKYO MX等の多サービス構成でも、暗号化しないPIDによる枠の消費を防ぎます。

TSRのPID枠は共有資源です。映像・音声サービス（ワンセグを含む）の全ESとPAT内の全PMTを保持し、独立したデータ専用サービスのESは通常配信へ追加しません。視聴サービスに含まれるBML等のデータPIDは保持します。初期登録済みのPAT・選択PMTを再登録しないことで枠の重複使用も避けます。
