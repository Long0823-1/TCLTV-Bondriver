# 0.6.0 XMLTV・自動更新・視聴優先の実機検証

2026-10-26、root導入済みTCL 32S5400 / G06の対応ファームウェアで検証しました。

## 番組表

- TVスキャン由来37サービスをchannelとして配信。M3Uのtvg-idとXMLTVのchannel idが対応します。
- 実放送のEITから番組名・説明・開始終了時刻を収集。確認時点で3,565番組。全局・全期間を必ず網羅する意味ではありません。
- 最終版XMLがXMLTV公式DTDを通過。UTF-8、日本語、UTC時刻、gzip展開、GET/HEAD、誤った接続キーの403拒否を検証。
- XML取得では選局せず、保存済み情報を配信。サービス再起動・APK上書き後もキャッシュを再利用できました。

## 自動取得と視聴への明け渡し

第2チューナーでの自動収集中に、通常の選局・TS接続による視聴要求を送りました。

- 通常の選局は1,587msで成功し、番組表の占有を解除。
- 2系統で視聴すると収集が待機。片方の視聴を閉じ、30秒の再接続待機後にそのチューナーで収集が再開。
- もう片方の視聴は85,068,684 bytesを受信し続け、TS同期エラー0。収集再開で視聴中の局が変わらないことを確認。
- 番組表専用の選局が処理中のタイミングでも通常選局を投入。背景側は中断（tune=24）、占有はpreemptedとなり、通常選局は1,689msで成功。
- 実際のx64 BonDriver DLLでも第2チューナーの041を20秒受信。42,833,920 bytes、同期エラー0、タイムアウト0、C/N 29.769dB。

待機・再開の実機確認は短時間の試験です。3時間の更新間隔は実装値であり、3時間経過を待つ長時間試験は実施していません。

## 自動テストとビルド

- EPG占有制御のCコードをNDKでビルドし、Androidエミュレーターで実行。視聴優先、チューナー独立、再接続猶予、古い占有ID・期限切れの拒否、キャンセル、EITだけのループバック転送が通過。
- JVMテストで局ID、UTC日時、XML特殊文字とUnicode、制御文字除外、未登録局・重複の除外、M3UのEPG URL、EIT/ARIB解析、CRC不良拒否が通過。
- NDKは -Wall -Wextra -Werror。TV APKの署名検証、Windowsセットアップのビルドを実施。
- スマホ0.4.1のM3U/XMLTV URLコピーはAndroid 11エミュレーターで検証。0.4.1の実スマホ検証と、任意の外部IPTVアプリでの番組表UI表示は未実施。

取得した実番組データや実際の接続キーは配布物へ同梱していません。消灯時の既存の確認範囲は[0.5.0](v0.5.0.md)に記載しています。
