# v0.4.0 検証記録（2026-10-25）

対応ファームウェアのTCL G06日本向け実機、Android 11。TVのAVプレイヤーを起動しない受信経路へ変更しています。以下はその変更後の測定です。

| 項目 | 結果 |
| --- | --- |
| 起動直後の入力初期化 | TVアプリ未起動の状態でTSIO 0を作成し、受信開始 |
| 再起動後の自動復元 | NHK総合・ETVの両系統が av_clear=1、別TSIDで復元 |
| 選局 | 第1系統をETV 023→NHK総合012、第2系統をETV 023へ切替成功 |
| DLLによる30秒同時受信 | x64第1系統46,924,800バイト、x86第2系統60,593,152バイト。同期エラー・タイムアウト0 |
| 012・023の映像/音声デコード | 各8.008秒、223/217フレームを出力。途中受信による初期ヘッダー警告あり |
| C/N | 同時DLL試験の最大値29.569dB / 28.969dB。専用スレッドから取得 |
| 枝番号とPMT | NHK総合1024/1025、ETV1032/1033/1034のPMTを受信 |
| スクランブル | 上記30秒の両サンプルの全受信PIDで0。追加音声PID 273も0 |
| データ放送 | 第1系統PID 320/352/353/354/368/369/370、第2系統320/352/353/354/355/356/357のDSM-CC CRC不良0 |
| 継続動作 | 選局後、PC接続なしでも両リングを排出。2系統目のECM・同期・CC・TEIエラー0 |
| ビルド | native -Wall -Wextra -Werror、muxテスト、WindowsセットアップEXE、APK v2/v3署名検証に成功 |

起動・選局直後は復号準備中のパケットが含まれます。カウンターを偽装したり、暗号化フラグを消したり、データPIDを削除したりする変更ではありません。

## 前面アプリとの同時利用

YouTube動画再生中の両系統受信で、同期エラー・全受信PIDのスクランブル・DSM-CC CRC不良が0でした。TV本体の映像が表示されていることも利用者が実画面で確認しました。TVerは再生状態（PLAYING）と、両系統16,051,364 / 17,183,876バイトの受信で同期エラー・スクランブル・DSM-CC CRC不良0を確認しました。TVerの保護された再生画面は内部キャプチャーで検証できないため、利用者がTV本体の実画面で映像・音声の両方が出ていることを確認しました。

実機試験はNHK総合・ETV中心です。別ECM群、PMT変更への自動追従、他機種・他ファームウェアは検証していません。放送TS、機器キー、ベンダーバイナリー、逆解析出力は配布しません。
